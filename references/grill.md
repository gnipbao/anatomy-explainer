# grill-me 审题与制作简报

`grill-me` 用来澄清视频要讲给谁、解决什么理解问题，以及如何验收。它位于主题输入与制作之间；成片可以另外包含预测题与迁移题，但这些教育材料不属于 `grill-me` 的接口。

## 已核对的接入目标

本次核对的安装来源包含两个不同名称的 Skill：`grill-me` 是显式调用入口，其 `SKILL.md` 声明转交给 `grilling`；`grilling` 才包含设计树、frontier 和分轮审题流程。这里没有打包或复制它们的原提示词，没有假设其支持原生 JSON API。

宿主提供 Skill 调用能力时，按精确名称加载 `grill-me`，再遵循其对 `grilling` 的转交。宿主只有文件读取能力时，先定位并读取实际安装的 `grill-me/SKILL.md`，再解析并读取它引用的 `grilling/SKILL.md`。不得把名称相似的其他 Skill 当作已加载依赖。

找不到入口、实现或对应工具时，明确说明外部 Skill 未加载；可使用本文件的审题流程作为显式 fallback，继续保存简报。fallback 不能写成“已成功调用 grill-me”。不安装外部包，不编造调用命令、JSON 导入方法或已发生的访谈。

## 稳定流程

1. **主题入场。** 提取主题、用户已经指定的条件与当前已知资料。把条件区分为用户明确要求、可查事实、代理默认值和待用户决定。用户指定官方视觉主题、豆包语音等条件时直接继承，不反复询问。
2. **事实先查。** 用子代理并行核对仓库能力、主题来源、依赖与可用语音等事实。查不到就记为未决事实，不让用户代替代理查找。没有子代理能力时自行完成只读核对并说明能力边界。
3. **画决策树。** 决策从受众与学习目标出发，再推导核心问题、覆盖范围、时长、语言、解释深度与画面策略。后一个决策依赖前一个答案时，不把两者放在同一轮。
4. **按 frontier 分轮。** frontier 只包含前置条件已解决、现在可以回答的用户决策。同轮列出整个 frontier，给每题编号、实际选项和推荐答案，让“是”能接受推荐；然后等待用户回答。事实探索仍在运行时，只等待依赖它的分支，其余前沿可先问。
5. **每轮重算。** 根据真实回答更新决策树与来源记录，再展开下一轮。推荐值、示例值或用户沉默都不算确认。用户已经明确回答的字段保持其来源，不重复拷问。
6. **锁定 brief。** 当 frontier 为空、未决事实不再影响方案时，汇总制作简报供用户确认共同理解。得到真实确认，或用户已明确授权代理决定剩余项且授权范围覆盖当前选择后，才把状态改为 `locked` 并进入制作；仍有问题则继续审题。创建这个 Skill 或提供示例文件本身不是一次完成的访谈。
7. **按 brief 制作。** 锁定的核心问题驱动事实模型、分镜和旁白；音频、字幕和成片复用该模型。发现新事实推翻关键条件时，重新打开相关分支，并保留原决策记录。

## 简报与来源记录

参考 [brief.json](../examples/brief.json)。这是本 Skill 自己的可审阅记录格式，外部 `grill-me` 无须支持 JSON 读写。

简报至少包括 `audience`、`core_question`、`duration_seconds`、`language`、`theme`、`tts`、`decision_provenance`、`open_questions` 和 `status`。每个选择标明来源：

| 来源 | 可以表示什么 |
| --- | --- |
| `user_request` | 用户本次原话明确固定的条件。 |
| `user_answer` | 真实访谈回答；保留简短的可核对依据。 |
| `verified_fact` | 代理找到的事实，附可查来源。 |
| `agent_default` | 可替换的默认建议，不能冒充用户确认。 |
| `example_assumption` | 用来演示文件形态的假设，不适用于真实生产授权。 |

`locked` 必须对应真实共同理解确认或明确的自主决策授权，且关键 `open_questions` 已解决。示例文件使用 `illustrative_not_user_confirmed`，不能靠复制示例或自动填默认值得到生产许可。若用户已明确授权在某些边界内自主决定，记录这项授权，再标明由代理在该范围内作出的选择。

## 独立的教育材料

[learning-checks.json](../examples/learning-checks.json)是可选的预测题与迁移题数据，用于设计科普视频的思考停顿；它没有访谈状态、用户回答或成绩，不是 `grill-me` 的输入输出协议。离线视频不能声称已获得观众答案或完成自适应教学。

令牌桶样例采用明确的请求计数简化：每秒补 `1` 枚、容量 `4`、每请求耗 `1`，无队列与透支，缺令牌即拒绝。初始 `4` 枚、同一时刻 `6` 个请求，通过 `4` 拒绝 `2`；空桶等 `2` 秒后同时来 `3` 个，通过 `2` 拒绝 `1`。事实依据及简化范围写在练习数据的 `rfc3290` 来源中，不能由审题推荐值改变。
